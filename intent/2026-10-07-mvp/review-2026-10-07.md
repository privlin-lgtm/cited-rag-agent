**a. Contradicts intent.md**

1. **Storage interface dropped.** Intent: "storage behind a small interface" carries over from `rag/interfaces.py`. Spec stack: "plain SQL through `postgres`", plan: one `lib/db.ts`. No interface named. Also breaks spec's own test story: porsager `postgres` speaks TCP; PGlite is in-process. "Same migrations on PGlite" needs either `@electric-sql/pglite-socket` in tests or a thin query interface with two drivers. Pick one.
2. **Open-question numbering.** Intent: Q1 embeddings, Q2 hosting, Q3 uploads. Spec cites "open question 1" for hosting, "open question 2" for uploads. Same questions, shifted numbers.
3. **Dependabot PRs.** Intent: Python code leaves "and its open Dependabot PRs close with it". Plan: code leaves in M1 (Wed), PRs close in M6 (Tue 13). Six days apart.
4. **Corpus fetch in CI vs browser fallback.** Spec 1 and 11: CI runs `corpus:fetch` on every env-branch push, M4 eval job too. Spec concern 5 and plan risk 3: blocked file gets downloaded by Paul in a browser into gitignored `corpus/files/`. That file exists only on Paul's machine. Any blocked source breaks every pipeline and eval run. Rejected alternative rules out committing files. Needs a third place (release asset, Vercel Blob, artifact).
5. **"Checked at the file and page it names".** Intent checks the model's named file and page. Spec: model never names them; file and locator come from DB by index. Stronger than intent, but intent wording should match.

**b. Not implementable from these files alone**

1. **Ingest idempotency vs re-ingest.** Spec 3: idempotent per (collection, sha256). Spec 11: re-ingest "if ingest code changed". With sha256 unique key, changed chunker produces zero new rows. Needs an ingest version (column or part of key) and delete-then-insert rule.
2. **Sentence splitter undefined.** One text block per sentence drives citations, check and highlight. Legal text has "§ 1005.33", "U.S.C.", "e.g.", numbered lists, PDF table rows with no terminal punctuation. Which splitter, what happens to a 600-token "sentence". Must be deterministic and re-runnable for the excerpt highlight.
3. **Citation check mechanics.** Verified in SDK 0.131.0 and docs: `search_result` GA, no beta header. Citation gives `search_result_index` (0-based across all `search_result` blocks in the whole request, all messages and tool results), `start_block_index`, `end_block_index`, `cited_text` = blocks concatenated, joiner unspecified. So: check `content[start:end]` block by block against stored chunk text, never `cited_text` as one string. Loop must keep a run-wide ordered list of every `search_result` sent. Spec says "the index points at a search result sent in this run" but not that index is global across rounds.
4. **`read_neighbours` result shape.** Citable or not? If citable, must be `search_result` blocks. Docs rule: a `tool_result` with any `search_result` must be all `search_result`, no mixed text. Not stated.
5. **Sonnet 5.5 loop specifics.** (i) `tool_choice` `any`/`tool` returns 400 on Sonnet 5.5; "must answer after round 6" needs `tool_choice: {type:"none"}` or tools removed. (ii) Thinking on by default; text between tool calls arrives as `thinking` blocks, empty unless `display: "updates"` (beta `thinking-display-updates-2026-08-18`) or `thinking: {type:"between_tools"}`. Spec's "one short sentence why it is searching" may never appear as text. Decide which mode. (iii) Thinking blocks must be echoed back unchanged every round (preserved thinking). (iv) `stop_reason: "refusal"` needs a branch.
6. **`max_tokens: 1500` includes thinking tokens.** With adaptive thinking on, answer can be cut mid-sentence. Decide: `between_tools` thinking, or effort `low`, or separate budget.
7. **Token count source.** `chunks.tokens` "estimated"; Voyage tokenizer differs from any local estimate. Use Voyage response `usage.total_tokens` or a stated estimator. Ceiling 600 vs context 32K: assertion never fires; the real guard is `truncation: false`.
8. **Rate-limit semantics.** Fixed hourly window keyed by `window_start` or sliding. Increment before or after model call; failed call counts or not. Atomic upsert needed. IP source header on Vercel. IP hash salt: unsalted sha256 of IPv4 reverses in seconds; privacy claim empty without a secret salt.
9. **Eval "hit".** Hit = retrieved chunk's (file, locator) in expected set? Page has several chunks. k applies to `search_documents` only or both tools. Threshold "set from first run" fine.
10. **Migrations tracking.** `scripts/migrate.ts` applies `.sql` files but schema has no applied-migrations table. Re-run on every push needs one.
11. **Feature-branch previews.** Vercel Preview env points every feature branch at Sandbox DB; migrations run only on env-branch push. A feature branch adding a migration deploys a preview against the old schema. Decide: previews run migrate at build, or previews accepted broken.
12. **Production ordering.** Merge to `master` triggers Vercel production deploy at once; `pipeline.yml` migration waits for Paul's environment approval. New code hits old schema. Either disable Vercel git deploy for production and deploy from the pipeline after migrate, or require every migration backward compatible.
13. **Undefined artifacts.** `AGENTS.md`, `REVIEW.md`, `.claude/agents/verifier.md`, hook behaviour ("workflow Phase 3a") exist only by name. Hooks block `TODO` and `git push origin master`; direct push to `sandbox`/`qa` not covered though spec says feature PRs merge into `sandbox`.
14. **Cost per question with `ANTHROPIC_MODEL` override.** `done` event prices need a table per model id; unknown id behaviour unstated.
15. **Fallback on Voyage failure.** Keyword fallback for the whole run, but `search_documents` tool then returns keyword hits under a semantic name; timeline label only. State it.

**c. Technical risks to change now**

- **Next.js 16.4.0 / React 19.3.0.** Next 16.4.0 published 2026-10-06, one day old. React 19.3.0 satisfies peer `^19.0.0`. Pin exact and lockfile. Note `next lint` gone in 16; lint command is plain eslint. Middleware renamed `proxy`; request APIs async.
- **TypeScript.** npm `latest` is 7.0.2 (Go compiler, 2026-07-08). `create-next-app@16.4.0` scaffolds `typescript: "^5"`. Plan's "version Next.js supports" = 5.x; pin `~5.9.3`. A bare `npm i -D typescript` gets 7 and an unverified `next build` type-check path.
- **PGlite.** `@electric-sql/pglite-pgvector@0.0.9` peer-pins `@electric-sql/pglite` to exactly `0.5.8`. Pin both exact, group them in Dependabot or one bump breaks install. Plus the TCP-vs-in-process gap in a.1. HNSW build in WASM slow but fine at fixture size.
- **unpdf 1.8.1.** Serverless PDF.js 5.6.205 bundle, worker inlined, no canvas. `extractText(data, {mergePages: false})` returns per-page `string[]` and `totalPages`: exactly what spec 3 and the 40-page check need. Node >= 22 avoids polyfill paths; Vercel default is 22. If Turbopack chokes on the bundle, add `serverExternalPackages: ['unpdf']`. Low risk.
- **search_result citations, one block per sentence.** Works (see b.3). Risks: hundreds of tiny blocks per round inflate input tokens; `cited_text` joiner unspecified so compare per block; same chunk returned in two rounds gives two indices, dedupe in display. Prompt cache: `cache_control` allowed on `search_result` blocks, set on the last tool_result each round for the growing-prefix saving spec assumes.
- **Supabase transaction pooler.** `prepare: false` correct (Supavisor port 6543, no prepared statements, no pipelining). Bigger issue: direct connection `db.<ref>.supabase.co:5432` is IPv6-only on Free and Paid. GitHub-hosted runners and Vercel are IPv4. Migrations from `pipeline.yml` over "the direct URL" fail. Use shared pooler session mode, port 5432, user `postgres.<ref>`. Also shared-pooler host contains a cluster index, copy from dashboard.
- **Voyage.** `voyage-4` exists: 32K context, 1024 dims, `input_type` and `truncation: false` supported, 200M free tokens, $0.06/M after. Documented Basic limits for `voyage-4`: 2000 RPM, 8M TPM; batch up to 1000 texts / 320K tokens per request. No reduced no-card tier appears on the rate-limits page. 0.3M-token corpus is a few requests, under a minute. Plan risk 2 (30-minute ingest, card decision) is overstated; keep backoff, drop the drama.
- **Anthropic spend.** $20 monthly cap vs 300 q/day at $0.04–0.06 = $12–18/day. Cap trips in two busy days; demo day could be dead. Add a daily output-token bucket in `usage_windows` or cut the global cap. Thinking tokens also absent from the cost estimate.
- **Vercel.** `maxDuration` 120 s fine (Pro default 300, max 800). Preview deployments on Pro have Vercel Authentication on by default: the "Sandbox preview URL" for interviewers needs protection off or a bypass token. Cron hourly ok on Pro.
